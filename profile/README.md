<p>工作室里养几十个号，最怕两件事：一是每个人自己拉一条线，月末账单一堆看不出花在哪；二是出口全挤在一条线路上，谁上传个素材，别人就集体卡住。带宽共享要解决的就是这两件事，但它不是插上就完，节点排错顺序、扩容时机、结算口径都得提前定。下面按时间线把从准备到月度复盘的六个节点拆开，每个节点给一个可检查的产出物。</p>

<h2>二、T-7 到 T-3：先把带宽需求算清楚</h2>
<p>容量表是后面所有决策的地基，算错这一步，选型和预算都会跟着错。别凭感觉说「够用」，按三个数倒推：同时在线的号数、单号峰值带宽、峰值持续时长。文本对话本身很轻，单号上行几十千比特就够，真正的尖峰来自附件上传、图片预览和后台同步。</p>

<h3>三个必须填的数字</h3>
<p>同时在线号数按最高峰算，别用平均数；单号峰值按实测，用浏览器开发者工具的网络面板挂一小时，看单次请求的峰值与持续几秒；峰值时长决定你需要的是瞬时带宽还是持续带宽，前者靠共享池就能扛，后者必须留固定余量。三个数乘起来再乘一点二的系数，就是共享池的下限。</p>
<h3>把「省掉的麻烦」也折成钱</h3>
<p>自己拉线不只是月租，还有排线、调试指纹环境、处理地址冲突的人力。一条自建线从采购到可用，常见要占掉半天到一天的人工；共享出口把这部分摊到服务商那边，换来的是可预期的月费。报价区间每月每条十几元到六十元不等，带宽按兆计费的方案另算，具体以服务商口径为准，仅供参考。</p>
<h2>三、T-1 到 D0：开通当天怎么分流</h2>
<p>开通当天最容易犯的错是一次性全量切过去，出问题连对照都没有。稳妥的做法是先切三成，跑通再放。分流规则建议写在配置文件里而不是靠记忆，规则要能回答一个问题：某个号出网时，走哪条线，权重多少，超限怎么办。</p>
<h3>分流的三种常见写法</h3>
<p>按号固定是最稳的一种，一个号绑一条线，互不影响，缺点是线路利用率低；按池轮转利用率高，但同一个号可能跳到不同出口，适合只做采集类、不需要身份连续性的任务；按权重加权介于两者之间，主线七成、备线三成，主线异常时自动倾斜。养号场景优先第一种，宁可多买几条线，也不要让号的出口随机漂。</p>
<h3>上线前的四步自检</h3>
<p>四步依次是：单条线单独连通性测试、两号同时在线看是否互相拖慢、断开一条线看业务是否自动切换、连续挂十二小时看有没有夜间掉线。四步都过再放全量。每一步都留截图和日志时间戳，后面定位问题时这比任何描述都管用。</p>
<h2>四、D+1 到 D+7：首周只做观察和记录</h2>
<p>首周不要急着调参数，先把基线数据攒出来。没有基线，后面任何一次「优化」都无法判断是变好还是变坏。建议每天固定两个时间点各记一次：上午十点和晚上八点，覆盖工作日峰值和休闲时段峰值。</p>
<h3>看哪几个指标</h3>
<p>丢包率、延迟中位数与九十五分位、单条线路的并发数、单位时间的连接失败次数。丢包超过百分之二、九十五分位延迟超过八百毫秒，基本可以判定这条线当天状态不佳。连续三天出现同类问题，就不要等首周结束，直接按换线流程处理。</p>
<h2>五、D+8 到 D+30：调档与结算</h2>
<p>调档的依据是首周数据，不是体感。加线的信号是峰值期间多条线同时饱和度超过八成；减线的信号是峰值期间长期低于四成且没有抖动。一次只动一到两条，动完观察三天，避免多因素叠加导致归因困难。</p>

<h2>常见问答</h2>
<h3>共享带宽会不会让号被关联？</h3>
<p>答：共享的是出口带宽资源，不等于共享同一个出口地址。正规做法是每条线独立出口、按号绑定，共享只发生在服务商那一侧的资源调度上。落地时要确认服务商给的是独立出口而不是所有人共用一个地址，这一点务必写进合同或订单备注。</p>
<h3>二十个号需要多少带宽？</h3>
<p>答：文本对话场景，二十个号同时在线，共享池留十到二十兆下行、五兆上行通常够用，尖峰靠突发余量吸收。如果涉及频繁上传图片或长文档，按实测峰值乘一点五重新算，不要套用别人的数字。</p>
<h3>分流规则写在哪一层比较好？</h3>
<p>答：写在代理客户端的配置里最直观，写在路由器或软路由上最省事，写在容器编排层最灵活。小团队建议从客户端配置起步，规则文件纳入版本管理，改动留提交记录，比口头交接可靠得多。</p>
<h3>什么时候该从共享换成独享？</h3>
<p>答：出现两类信号就考虑换：一是同一时段总是固定几个号受影响，说明它们在抢同一段资源；二是业务对出口连续性要求提高，比如需要长期保持同一地址的登录态。独享的成本更高，按实际需要逐条替换，不必一次性全换。</p>
